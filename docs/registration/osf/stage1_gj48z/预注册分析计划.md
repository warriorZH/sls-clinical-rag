# 预注册分析计划：专家封存测试集 v1

本计划须在**任何模型对封存候选池打分之前**定稿并留存时间戳，例如上传到 OSF，或提交到带时间记录的 git 仓库。
定稿后如有改动，记入文末“偏离记录”，论文中如实说明。

## 1. 数据与冻结顺序

1. 阶段1仲裁完成，生成 `final_questions.json`，记录其 SHA256。
2. 在服务器上生成候选池 `sealed_pools.jsonl`，记录 SHA256：
   - 每题 BM25 前 20 条；
   - 检索只使用问题文本；
   - 不插入参考答案。
3. 阶段2仲裁完成，生成 `phase2_gold_labels.jsonl`，记录 SHA256。
4. **以上三个文件冻结后**，才能运行模型打分。每个模型和配置只运行一次，全部结果都要报告。

## 2. 比较对象

所有方法都对**同一份 20 条候选池**重排，每题选出前 2 条。证据输入采用标题加上下文版本，与标注时显示的文本一致。

| 方法 | 说明 |
|---|---|
| Support-CE | 现有 mDeBERTa 模型，种子 42/2026/3407 |
| Relevance-CE | 同上，只是训练标签换成相关性 |
| BM25 原始排序 | 无学习的基线 |
| bge-reranker-v2-m3 | 零样本，公开强基线 |
| Qwen3-Reranker-0.6B | 零样本，公开强基线 |
| （可选）LLM 逐点判断 | 例如 Qwen2.5-7B 零样本判断“是否完整支持某要点” |

模型检查点、预算（Top-2）全部固定，不在封存集上调任何参数，也不使用阈值。

## 3. 主假设与主指标

**H1：** 在封存集上，Support-CE 的 Top-2 必要点覆盖率高于 Relevance-CE。

**指标定义：**

- 覆盖率：所选 2 段证据对本题必要点的完整支持（金标=2）取并集，再除以该题要点数。
- 先在每题内对 3 个种子取平均，再在全体题目上取平均。

**检验方法：**

- 计算均值差。
- 按题目做配对 bootstrap，10000 次，报告 95% CI。
- 下界大于 0，视为支持 H1；否则如实报告为未支持。

## 4. 次要分析

以下比较统一用 Holm 方法做多重比较校正。

- Support-CE 分别对比 BM25、bge-reranker-v2-m3、Qwen3-Reranker-0.6B 的覆盖率差。
- 全覆盖率：所有要点都被完整支持的题目比例。
- 选入非支持率：所选证据中不完整支持任一要点的比例。
- 排序质量：池内 nDCG@10。增益取该证据对各要点支持分数的最大值，2 或 1 或 0。
- 候选池上限：20 条证据全部选入时的覆盖率，用来说明召回瓶颈。
- 部分支持口径：把“部分支持”计入后的覆盖率，作为敏感性分析。

## 5. 分层（描述性，不做显著性结论）

- 题型：诊断解释题与治疗原则题。
- 来源层：从未处理过的新病例（fresh_med）与原测试集留出病例（heldout_med）。
- 证据来源：教材、古籍、其他病例记录。
- 种子间差异：报告每个种子的结果及标准差。

## 6. 标注质量报告

- 阶段1：
  - 要点判定的 κ；
  - 程序草拟要点的保留、修改、删除比例；
  - 题目排除数及原因。
- 阶段2：
  - 主指标标签（完整支持与否）的 Cohen κ 或 Krippendorff α，附 95% CI；
  - 三级支持度的线性加权 κ 或序数 α；
  - 相关性的 κ；
  - 仲裁比例。
- （可选，在金标冻结后进行）用 AI 对同一候选池标注，报告 AI 与专家金标的 κ，作为标注成本分析。

## 7. 排除与缺失

- 只有阶段1判定排除的题目不进入分析。
- 金标冻结后，不再删除任何题目或候选。
- 证据文本缺失的候选按不支持计，并报告数量。
