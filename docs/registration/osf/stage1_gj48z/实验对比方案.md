## 2. 输入文本与选择规则

- **查询**：`question_final`。它就是检索和标注时使用的问题文本，包括末尾一句“请解释……”或“请说明……”。
- **证据**：`context_text`，即教材、古籍条目的标题加上下文；病例记录为原片段。`context_text` 为空时改用 `text`。这与标注表中的“证据文本”逐字一致。
- **选择**：每种方法对同一题的 20 条候选打分，取分数最高的 2 条。分数相同时，BM25 名次靠前者优先。
- **排序**：计算 nDCG@10 时，用同一分数和同一同分规则对 20 条候选排序。

## 3. 比较方法

| 方法 | 运行次数 | 固定设置 |
|---|---|---|
| Support-CE | 3（种子 42/2026/3407） | E3 所用的检查点 `experiments/stage4_retraining/support_<种子>/best_checkpoint.pt`。加载、编码和打分方式与 E3 完全相同（见下方说明） |
| Relevance-CE | 3（种子 42/2026/3407） | 同上，检查点为 `relevance_<种子>/best_checkpoint.pt` |
| BM25 原始排序 | 1 | 不调用模型，取候选池名次 1、2 |
| bge-reranker-v2-m3 | 1 | 零样本；固定使用 hf-mirror 上的版本 `953dc6f6`；transformers 序列分类；按（查询，证据）顺序输入；最大长度 1024；fp32；分数为 logit |
| Qwen3-Reranker-0.6B | 1 | 零样本；固定使用版本 `e61197ed`；使用官方提示模板；分数为 P(yes)；最大长度 2048；fp32；指令固定为 `Given a Traditional Chinese Medicine clinical case and a question about it, retrieve passages that help answer the question` |
| （可选）LLM 逐点判断 | 0 | **本次不运行**，原因见 D6。原设计：Qwen2.5-7B-Instruct，零样本，按候选逐条判断，只给问题和证据，不给金标要点；提示词见 `server_score.py` 中的 `LLM_JUDGE_PROMPT`；分数为 P(是)/[P(是)+P(否)] |

- 所有检查点和设置都在封存集打分前固定，不在封存集上调整任何参数，不使用阈值。
- 最大长度按实测设置，保证公开模型不截断：问题加证据最长 679 字。CE 模型沿用训练时的长度，截断条数记入运行清单。
- 精度：服务器为 Tesla P40，不支持 bf16，fp16 吞吐也很低，所以全部方法都用 fp32。实际精度记入运行清单。

**Support-CE / Relevance-CE 的加载、编码和打分方式**

依据服务器上 E3 的 `stage5_real_retrieval_v1_2/score_three_seed_review.py` 和 `stage4_retraining/train_stage4.py` 中的 `predict()`：

- 先按 `/home/zph/models/mdeberta-v3-base` 建立二分类模型（fp32），再载入检查点中的 `model` 权重。
- 输入 = `[CLS]` + 问题的前 160 个 SentencePiece 词元 + `[SEP]` + 证据的前（509 − 问题长度）个词元 + `[SEP]`，只给 input_ids 和 attention_mask。
- 按长度排序，每批 4 条；分数取 softmax 后第 1 类的概率。

**复现核对**：校准集阶段，每个 CE 检查点都要用上述方式重新给 E3 已打分的 200 条候选（`candidates_unlabeled.jsonl` 中非训练集的行，等距抽取）打分，并与 E3 保存的 `parent_<目标>_<种子>/expanded_context_scores.npy` 比对。要求最大差小于 0.001；有检查点哈希记录的，还要与 E3 记录一致。不通过的方法不进入封存集打分。

## 4. 运行规则

1. **冒烟测试**：先用 5 道校准题（开发集，不属于封存集）跑通全部方法，即 `--target calib`。CE 检查点同时做复现核对。
2. **留存时间戳**：把本方案、预注册计划和 `FREEZE_MANIFEST.json` 上传 OSF，或提交到带时间记录的 git 仓库。
3. **一次性运行**：在封存集上运行全部方法，即 `--target sealed`。
   - 脚本要求每个方法先以相同设置通过校准集测试，并且拒绝覆盖已有结果。
   - 如果因故障确需重跑，必须写明原因。旧结果会被保留，全部如实报告。
4. **金标隔离**：金标文件不上传到服务器，打分脚本只读取问题文本和候选池。
5. **全部报告**：计划内的方法全部报告；未能运行的方法也要写明原因。每次失败的运行都保留在运行清单的 `failures` 中。

## 5. 指标定义

对每题 q：要点集合为 P_q，选出的 2 条证据为 S_q；s(c, p) 表示候选 c 对要点 p 的金标支持分（2/1/0）。

| 指标 | 每题取值 | 说明 |
|---|---|---|
| **覆盖率（主指标）** | \|{p ∈ P_q : max_{c∈S_q} s(c,p) = 2}\| / \|P_q\| | 对所选 2 条证据的完整支持取并集 |
| 全覆盖率 | 1[覆盖率 = 1] | 所有要点都被完整支持 |
| 选入非支持率 | \|{c ∈ S_q : max_p s(c,p) < 2}\| / 2 | 所选证据中没有完整支持任何要点的比例 |
| nDCG@10 | DCG@10 / IDCG@10 | 增益 g(c) = max_p s(c,p) ∈ {0,1,2}，取线性增益，折扣为 log2(i+1)；池中没有任何支持（IDCG = 0）的题不参与计算，单独报告题数 |
| 候选池上限 | 20 条全部选入时的覆盖率 | 与方法无关，用于说明召回瓶颈 |
| 部分支持口径覆盖率 | 把条件 “= 2” 换成 “≥ 1” | 敏感性分析 |

- **CE 模型的汇总**：先按种子分别计算，再在每题内对 3 个种子取平均，最后在全体题目上取平均。
- **其他方法**：每题只有一个值，直接在全体题目上取平均。

## 6. 统计检验

**主假设 H1**

- 设 d_q 为每题 Support-CE 覆盖率（种子平均）减去 Relevance-CE 覆盖率（种子平均），检验统计量为 mean_q d_q。
- 按题目做配对 bootstrap：重抽样 10,000 次，随机种子 20261026，取百分位法 95% CI（线性插值）。
- 判定规则：CI 下界大于 0 时视为支持 H1；否则如实报告为未支持。

**次要比较**

- 所有比较都使用同一套 bootstrap 重抽样下标。
- 双侧 p 值：p = min(1, 2·min[(#{d* ≤ 0}+1)/(B+1), (#{d* ≥ 0}+1)/(B+1)])。
- Holm 校正在每个指标的比较家族内进行，α = 0.05：

| 家族 | 比较 | 检验数 |
|---|---|---|
| F1 覆盖率 | Support-CE 对 BM25、bge-reranker-v2-m3、Qwen3-Reranker-0.6B | 3 |
| F2 全覆盖率 | Support-CE 对 Relevance-CE、BM25、bge、Qwen3 | 4 |
| F3 选入非支持率 | 同上 | 4 |
| F4 nDCG@10 | 同上 | 4 |
| F5 部分支持口径覆盖率 | 同上 | 4 |

- 各方法的各项指标同时报告点估计和 95% bootstrap CI。
- 可选的 LLM 方法不放入任何家族，只报告未校正的 CI。

## 7. 分层、种子与标注质量

**分层**（描述性，不做显著性结论）：

- 题型：诊断解释题、治疗原则题。
- 来源层：fresh_med 与 heldout_med，并与题型交叉。
- 证据来源：教材、古籍、其他病例。报告两项内容：
  - 各方法所选证据的来源构成，以及各来源中完整支持证据所占比例；
  - 候选池中各来源的完整支持产出。

**种子**：Support-CE、Relevance-CE 分别报告每个种子的结果，以及种子间标准差。

**标注质量**：

- 阶段1：要点判定 κ；程序草拟要点的保留、修改、删除比例；排除题数及原因。
- 阶段2：
  - 完整支持与否：Cohen κ、Krippendorff α，附 95% CI；
  - 三级支持度：线性加权 κ、序数 α；
  - 相关性 κ；
  - 仲裁比例。
- 补充报告：正例数、正一致率与负一致率、PABAK、Gwet AC1，用来应对正例稀少造成的 κ 悖论。
- 计划第 6 节中的可选项“AI 与专家金标的 κ”：本次金标本身由 AI 生成，不适用。

**探索性分析**（未预注册，单独列出，不用于结论）：

- X1 分级覆盖率：完整支持记 1，部分支持记 0.5。
- X2 条件分析：只在候选池中至少有一个要点获得完整支持的题目上重做 H1。
- X3 误导率：所选证据中被标为“同病异证或条件不符”的比例。
- X4 相关但不支持率：所选证据中相关性为 1、但没有完整支持任何要点的比例；另报相关性为 1、但对任何要点都不支持（全为 0）的比例。
- X5 所选证据的相关率。
- X6 可选的 LLM 逐点判断结果。
- X7 种子间 Spearman 相关。
